# The Tauri integration

`<ScoreEditor>` takes bytes and gives back bytes; it never touches files
(decision 7). In a Tauri 2 app, the native side comes from
[`tauri-plugin-donizetti`](../../crates/tauri-plugin/README.md) and its typed
client [`@donizetti/tauri`](../../packages/tauri/README.md):

- **Scores** read with their SHA-256 hash and written in one rename, refused
  when the file changed on disk since it was read (the hash guard, as jerome
  guards its own files).
- **The soundfont**: MuseScore General 0.2.0 (SF3, MIT, about 38 MB)
  downloaded on the user's request, checked against its pinned size and
  SHA-512, installed with its notice, read for the player and removed
  ([donizetti_soundfonts](../../crates/soundfonts/README.md); decision 10).
- **PDF export**: the score's SVG pages to one PDF
  ([donizetti_pdf](../../crates/pdf/README.md)).

## Registering the plugin

In the app's `Cargo.toml`, by git (pinned to a commit) or by path
(decision 11):

```toml
tauri-plugin-donizetti = { git = "https://github.com/Federiker/donizetti", rev = "<commit>" }
```

then in the app's builder:

```rust
tauri::Builder::default()
    .plugin(tauri_plugin_donizetti::init())
```

`init()` keeps the soundfont in the app's data folder,
`app_data_dir()/soundfonts`. To keep it elsewhere:

```rust
.plugin(
    tauri_plugin_donizetti::Builder::new()
        .soundfont_dir(folder)
        .build(),
)
```

The window's capability (`src-tauri/capabilities/*.json`) allows the
commands:

```json
{ "permissions": ["core:default", "donizetti:default"] }
```

`donizetti:default` allows every command; each also has its own
`donizetti:allow-<command>` and `donizetti:deny-<command>` (for example
`donizetti:allow-read-score`), listed in
[the generated reference](../../crates/tauri-plugin/permissions/autogenerated/reference.md).
The score and PDF commands take any path the window passes, as Tauri's own
file plugin does without a scope: the capability is the boundary, so grant
it only to the app's own windows.

In the app's TypeScript, `@donizetti/tauri` (with `@tauri-apps/api`) calls
them:

```ts
import { exportPdf, installSoundfont, readScore, readSoundfont, writeScore } from "@donizetti/tauri";

const { bytes, hash } = await readScore(path);
// … <ScoreEditor source={bytes} soundfont={readSoundfont} onSave={…} />
const newHash = await writeScore({ path, bytes: saved.bytes, expectedHash: hash });
```

## Commands

Each command is `plugin:donizetti|<command>`; the client's function is given
in brackets. Commands that touch the disk or the network run on a blocking
thread.

| Command | Takes | Answers |
| --- | --- | --- |
| `read_score` (`readScore(path)`) | `path` | `{ bytes, hash }` |
| `write_score` (`writeScore({ path, bytes, expectedHash? })`) | the bytes, the path, the expected hash | the new hash |
| `soundfont_status` (`soundfontStatus()`) | nothing | `{ soundfont, installed, installing }` |
| `install_soundfont` (`installSoundfont(onProgress?, { signal? })`) | a channel for `{ received, total }` | the new status |
| `cancel_soundfont_install` (through `signal`) | nothing | nothing |
| `read_soundfont` (`readSoundfont()`) | nothing | the soundfont's bytes |
| `remove_soundfont` (`removeSoundfont()`) | nothing | the new status |
| `export_pdf` (`exportPdf(pages, path)`) | `pages` (SVG text, one per page), `path` | nothing |

### Scores and the hash guard

The hash is SHA-256 in lower-case hexadecimal (64 characters).

- `read_score` answers in one binary message: the hash's 64 characters, then
  the file's bytes, so a score never travels as JSON (a number per byte). The
  client splits the two.
- `write_score` sends the bytes as the request's raw body; the path travels
  in the `Donizetti-Path` header, percent-encoded as UTF-8
  (`encodeURIComponent`, since a header holds only ASCII), and the expected
  hash in `Donizetti-Expected-Hash`. Where Tauri falls back to `postMessage`
  (Android, or a webview that blocks its protocol) the body arrives as an
  array of numbers, which the plugin also takes.
- The bytes are written to a temporary file in the score's folder
  (`.<name>.<random>.tmp`), flushed to disk, then renamed over the score: the
  file on disk is always the old score or the new one. On macOS and Linux a
  replaced file keeps its permissions.
- With an expected hash (the one `readScore` or the last `writeScore` gave),
  the file must still be the one the app read. It is checked before writing
  and again just before the rename; if another program changed it, nothing
  is written and the save fails with `changed_on_disk`, with both hashes. A
  file that is no longer there counts as empty. Without an expected hash (a
  new file, Save As, or the user choosing to overwrite) the file is written
  whatever is there.

### The soundfont

- `soundfont_status` says what is on offer (`soundfont`: name, version,
  licence, address, size, SHA-512, file name), whether it is installed
  (`installed`: its `path`, its notice's `noticePath` and `bytes`, or null)
  and whether a download is running (`installing`). A file counts as
  installed when it has the pinned size; the download checks the bytes.
- `install_soundfont` downloads only when asked, over HTTPS from the pinned
  address (no redirects, no proxy), checking the size and SHA-512 as it
  arrives. It writes `MuseScore_General.sf3.part`, then renames it into place
  with its notice, `MuseScore_General.sf3.LICENSE.md` (the acknowledgements
  and MIT licence that must accompany it; a host's About shows it). A failed
  or cancelled download leaves nothing behind. An installed soundfont is not
  downloaded again. The channel hears `{ received, total }` at the start,
  every 256 KiB and at the end. One download runs at a time.
- `cancel_soundfont_install` stops the running download, which then fails
  with `soundfont_cancelled`; the client sends it when `signal` aborts.
- `read_soundfont` answers the bytes as a binary message, for
  `<ScoreEditor soundfont>`; `remove_soundfont` removes the file, its notice
  and any half download.

### PDF export

`export_pdf` makes one page of each SVG, the size of its `width` and `height`
(CSS pixels at 96 to the inch, as OpenSheetMusicDisplay writes them: a page
of 794 × 1123 px is A4, 595.5 × 842.25 pt), with the music as vectors and the
text (titles, lyrics, chord symbols) as real, selectable text in the
computer's fonts. A font family the computer lacks falls back to one it has;
a page with text on a computer with no fonts at all is refused
(`pdf_no_fonts`) rather than written without its words. The file is written
in one rename, as a score is.

## Errors

Every failure reaches the app as `{ code, params }`, never English text; the
client throws it as a `DonizettiPluginError` with `code` and `params`.
`detail` is the operating system's or a library's own words, for logs, not
for the interface. Pages are numbered from 1.

| Code | When | `params` |
| --- | --- | --- |
| `read_failed` | A score could not be read (or checked before a save) | `path`, `detail` |
| `write_failed` | A score or PDF could not be written; the file is as it was | `path`, `detail` |
| `changed_on_disk` | The file is not the one the app read; nothing was written | `path`, `expectedHash`, `actualHash` |
| `invalid_request` | A `write_score` without its path header, or a body that is not bytes | `detail` |
| `internal` | The command's thread stopped | `detail` |
| `soundfont_busy` | Another download is running (install or remove) | none |
| `soundfont_cancelled` | The download was cancelled | none |
| `soundfont_download_failed` | The server could not be reached or answered otherwise | `reason` (`setup`, `unreachable`, `status`, `interrupted`), `status` for an HTTP answer |
| `soundfont_verification_failed` | The file is not the pinned soundfont (size or SHA-512) | none |
| `soundfont_not_installed` | `read_soundfont` with nothing installed | none |
| `soundfont_storage_failed` | A soundfont file could not be written, read or removed | `path`, `detail` |
| `pdf_no_pages` | `export_pdf` with no pages | none |
| `pdf_invalid_svg` | A page is not an SVG that can be read | `page`, `detail` |
| `pdf_no_fonts` | A page has text and the computer has no fonts | `page` |
| `pdf_conversion_failed` | svg2pdf could not convert a page | `page`, `detail` |

The client adds two of its own: `invalid_response` (the plugin answered
something of the wrong shape; `command`, `detail`) and `unknown` (the call
failed in a way that is not the plugin's, such as a command the capability
does not allow; `detail` is Tauri's text). An answer of the wrong shape is
an error, never a substitute value.
